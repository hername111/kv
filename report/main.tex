\begin{abstract}
本文报告一个使用 Rust 2024 实现的教学型关系数据库。系统以 4 KiB 磁盘页为基础，贯通 superblock、空闲页管理、slotted page、B+Tree、缓冲池、事务与 MVCC、SQL 处理、MySQL Wire Protocol、HTTP API 和 React 工作台。2026 年 7 月 16 日的复现实验中，74 个 Rust 测试和 87 项端到端协议/持久化测试全部通过，前端生产构建成功。项目参考 SQLite、PostgreSQL、MySQL InnoDB 和 CMU BusTub 的公开设计资料，但代码为小组独立实现；报告同时说明了结构差异、测试对比和当前限制。
\end{abstract}

\section{项目名称}

\textbf{项目名称：}KV Database——基于 Rust 的教学型关系数据库。

项目采用 Cargo workspace 组织六个核心 crate，并提供 MySQL TCP 接口和 Web 工作台。其定位不是对成熟数据库做功能复刻，而是以可运行、可观察、可测试的规模展示一条完整链路：SQL 输入经过词法、语法、计划和执行阶段，进入事务层与 B+Tree 存储，最终落入磁盘页。

\section{项目背景与目标}

\subsection{项目背景}

数据库系统同时涉及数据结构、文件系统、网络协议、并发控制和编程语言。直接调用现有数据库只能看到接口结果，难以观察 SQL 如何变成执行计划、记录如何组织为页面、事务提交如何影响可见性以及重启后元数据如何恢复。因此，本项目选择从零实现规模受控的数据库内核，以 Rust 的所有权、trait、错误传播和线程安全机制串联课程知识。

\subsection{拟解决的问题}

项目重点解决以下问题：一是将变长记录可靠地编码到固定大小页面，并拒绝越界或损坏数据；二是通过 B+Tree 和缓冲池完成有序存取及页面复用；三是建立从 SQL 到事务写集再到磁盘的执行路径；四是通过 MySQL 协议和 Web 界面提供可验证入口；五是用自动化测试覆盖正常功能、输入边界和重启持久化。

\section{系统设计与实现思路}

\subsection{总体架构}

\begin{verbatim}
MySQL client --> network --+
                           +--> SQL --> txn --> storage --> kv.db
React UI ----> HTTP API ---+
\end{verbatim}

\begin{enumerate}[label=\arabic*.]
\item \code{kv-common}：共享类型、错误定义和 \code{Pager} trait。
\item \code{kv-storage}：页面编解码、磁盘 Pager、LRU 缓冲、B+Tree、catalog。
\item \code{kv-txn}：事务生命周期、读写集、版本链、可见性和表级锁。
\item \code{kv-sql}：Lexer、Parser、Planner 和 Executor。
\item \code{kv-network}：MySQL 握手、包解析、分片重组和结果集编码。
\item \code{kv-server}：组装 TCP 服务与本地 HTTP 演示 API。
\end{enumerate}

依赖保持单向：接口层调用 SQL 执行层，执行层依赖事务和存储，底层不依赖前端。该划分使各层可以独立单元测试，也让同一个执行器同时服务 MySQL 客户端和 Web 工作台。

\code{SlottedPage} 的页头保存 page id、tuple 数量、\code{free\_start}、\code{free\_end} 和标志位。槽目录从页首向后增长，tuple 数据从页尾向前增长，槽项记录 tuple 的偏移和长度。\code{validate\_layout} 检查槽目录边界、tuple 范围和重叠关系，使损坏数据返回 \code{KvError} 而不是触发越界访问。

\subsection{核心算法}

\textbf{B+Tree。}内部节点保存分隔键和子页号，叶节点保存有序键值并以 \code{next} 相连。插入先沿分隔键定位叶页，再按序插入；节点超容量时分裂并向父节点上推分隔键，根分裂时创建新根。叶链支持范围扫描。当前删除仅覆盖基础路径，尚未实现完整合并与再平衡。

\textbf{页面分配与缓存。}\code{DiskPager} 从空闲页链表优先分配页面，没有空闲页时扩展文件。打开文件时检查长度、魔数、版本、页号范围和链表环。\code{BufferedPager} 用 Mutex 保护 LRU 页面副本；释放页面时显式失效缓存，避免页号复用后读到旧内容。

\textbf{SQL 执行。}输入依次经过 Lexer、Parser、Planner 和 Executor。执行器读取 catalog 与 B+Tree，并在事务上下文中处理查询或写入。事务写操作先进入写缓冲与写集，提交时应用，回滚时丢弃；MVCC 版本链负责可见性判断，表级锁限制冲突访问。

\textbf{协议与展示。}MySQL 服务实现握手、命令包、OK/ERR 和结果集编码，可重组 TCP 分片，并拒绝超过 8 MiB 或截断的包。HTTP API 提供 \code{GET /api/state}、\code{POST /api/query}、\code{POST /api/reset}，请求体上限为 64 KiB。React 工作台从真实 API 获取 schema、记录、执行阶段和后端耗时，不在前端复制 SQL 规则。

\begin{lstlisting}[language=bash]

\subsection{结果分析与局限}

实验表明，项目已完成从协议输入到磁盘持久化的最小闭环，且正常功能和多类边界条件能够稳定返回预期结果。与只运行单元测试相比，87 项端到端测试额外覆盖真实 TCP 连接、服务器重启和文件复用，因此对模块集成与持久化结论提供了更强证据。

但“正常重启后可恢复”不等于“崩溃安全”。项目没有 WAL、checkpoint 和崩溃原子提交；B+Tree 未实现完整删除再平衡；MVCC 版本主要位于内存；锁粒度为表级；MySQL 协议仅覆盖项目 SQL 子集。因此本实验只能得出当前功能范围内正确、可复现的结论，不能宣称达到生产数据库的 ACID、并发度或兼容性。

\subsection{与原项目的区别、修改和改进}

\begin{table}[H]
\centering
\caption{参考系统与本项目的对比分析}
\begin{tabularx}{\textwidth}{p{2.1cm}p{4.3cm}X}
\toprule
维度 & 参考系统 & 本项目的区别与改进\\

对比可见，本项目没有追求与 SQLite、PostgreSQL 或 InnoDB 的性能和功能对等，而是缩小数据结构后补充严格边界检查、跨重启测试和双入口展示，使各层在课程规模内可运行、可观察、可验证。相应代价是缺少 WAL、复杂并发控制、完整索引维护和崩溃恢复，这些差异已在实验结论中明确限定。
